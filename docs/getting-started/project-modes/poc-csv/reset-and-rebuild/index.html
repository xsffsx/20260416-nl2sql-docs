Reset a project

Created October 7, 2026 · Last updated October 8, 2026

Reset returns an editable project to its first-use state. It removes its Active Snapshot, draft, model, Knowledge, Instructions, Schema RAG, project QA/Chat/API history, and uploaded POC CSV tables. The project entry and connection settings remain. QA is unavailable until you publish new data or import a valid snapshot.

The screenshots use the isolated poc_csv_reset project and the three files from Import CSV data and run your first QA. Select your project in the upper-right picker. Keep your original CSV files if you plan to upload them again. IMPORT_DIR projects can also Reset after backing up Active. Reset preserves the configured package and ownership; restart to import that package again. Keep the required external query data available.

1. Open the project's Configuration page​

In the left menu, open Artifact → Configuration. The page title is Active Snapshot. Check the project picker and Current Snapshot · Active, then locate Reset project next to Export.

2. Export the Active Snapshot​

Click Reset project. The app first exports and validates the current Active Snapshot, downloads a ZIP named after the export folder, then opens the confirmation dialog. Keep the downloaded ZIP. The dialog displays the exact folder name; Reset is disabled until you enter it.

If the Pod's export directory is permission-denied or read-only, the backend logs WARN and skips only server disk saving. The ZIP still downloads automatically, and the dialog shows Server disk save skipped. Keep the downloaded archive: no server-side backup was saved. Reset verifies the complete downloaded package against the still-current Active; it does not require a writable export directory. Other failures, including disk-full or invalid export content, still block Reset.

If the project has no Active Snapshot, Reset does not export or download anything. It opens a cleanup confirmation without a folder-name input so unpublished content, history and owned CSV tables can still be removed. The server rechecks Active absence under the project lock; if Active appeared meanwhile, Reset is rejected. This is not an automatic deletion on opening the dialog.

3. Confirm the folder name and Reset​

Read the deletion list. When Active was exported, type the export folder name shown in the dialog exactly into the confirmation field. Check that Reset project becomes enabled, then click it. Do not type the ZIP filename with .zip or invent a name. With no Active, simply review the deletion scope and confirm Reset; no backup name is required.

A wrong name cannot start Reset. If Active changed after export, export that current snapshot again before resetting. Existing runtime or Publish-status warnings do not disable Reset; the backup and project cleanup must still complete successfully.

4. Check the empty project state​

After Reset, Configuration shows No active snapshot, No tables to publish, and Guide with 0 of 7 Schema/QA steps complete. Open NL2SQL QA Console: it says Publish your data to start asking questions. A question cannot reach the MCP tool without an Active Snapshot.

5. Upload the same CSV files again​

Open Artifact → Schema and import the original three CSV files again. Follow the Import → Review CSV → Create schema stages in the CSV import guide. The preview should list singer, concert, and singer_in_concert without table-name conflicts. Confirm 3 tables · 22 rows, then click Create schema.

The three tables now appear in Schema, but they are Pending Publish and QA still has no Active Snapshot.

6. Publish a new Active Snapshot​

Click Deploy, then on Configuration review the Unpublished changes and click Publish. Complete the review and confirmation dialogs as shown in the CSV import guide. Wait until Current Snapshot · Active appears. The new snapshot contains the reimported model; Knowledge and Instructions removed by Reset do not return merely because you uploaded the same CSV files.

7. Verify QA works again​

Open NL2SQL QA Console and ask List all singer names in concerts in year 2014. for these sample files. Confirm Success, 6 rows, and the generated SQL.

The exported ZIP preserves the old snapshot configuration. To import it later, first restore any Query DB tables and rows it requires; the snapshot export does not replace the CSV data you originally uploaded.
