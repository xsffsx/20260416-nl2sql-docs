Import CSV data and run your first QA

Created October 7, 2026 · Last updated October 17, 2026

Use the application's Guide to take a project from CSV files to a verified NL2SQL answer. The same seven steps appear in Guide and are exercised by the mock Playwright E2E. Screenshots below are captured by that E2E run and published here from the same image buffers. The captures use the isolated poc_csv_reset project; select your own project in the upper-right picker. It must use POC_CSV_SQL_EXECUTE_RESULT mode and have a writable Query DB. See Local Development to start the app.

Download these sample CSV files into one folder before starting:

  • Download singer.csv
  • Download concert.csv
  • Download singer_in_concert.csv

1. Import schema​

On Artifact → Schema, confirm the project picker shows your project. Open Guide in the lower-left corner, choose Schema & QA → Import schema, then click the highlighted Import button. Opening the source picker does not change project data. The guide then highlights CSV data · POC; CSV model metadata does not upload query rows.

2. Review CSV​

The preview proposes tables named singer, concert, and singer_in_concert. Select each file and review its table name, columns, data types, and sample values. Fix any issue before continuing. If you open this step before uploading files, Guide explains the prerequisite and keeps Continue unavailable.

3. Create schema​

The confirmation stage summarizes 3 tables · 22 rows. Check the table names and row counts, then click Create schema. This imports the CSV rows and creates a Draft. A Draft is not yet available to QA; it does not become Active until you publish it. Opening Create schema before a valid CSV preview shows the prerequisite and disables creation.

4. Deploy​

After creation, the Schema page shows the imported models. Click Deploy to open Active Snapshot and inspect the Draft. Deploy opens the snapshot workspace; the Draft is still unpublished at this point.

5. Publish​

On Active Snapshot, select Publish. Review the changes in the first dialog, then confirm Publish in the final dialog. Wait for Current Snapshot to show Active and Guide to say Your data is ready. This is the point where the imported data becomes available to QA.

6. Check readiness​

Open Check readiness from Guide. On Diagnostics, click Refresh report and wait for the project health check. Guide advances only when runtime readiness reports ready. This health check is different from QA Smoke: it checks project and Active Snapshot readiness but does not submit the example question.

7. Try Ask​

Choose Go to Try Ask. In NL2SQL QA Console, submit this question and wait for the result:

List all singer names in concerts in year 2014.

The example should return Success, 6 rows, the singer names, and generated SQL. Justin Brown appears twice. Guide completes only after the application returns a successful QA result.

To clear the project and repeat the exercise, follow Reset a project.
