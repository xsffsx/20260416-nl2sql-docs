2. REST Endpoint: call the existing NL2SQL API​

The Rhesis REST Endpoint was configured against the existing API. Each test sent POST /api/nl2sql?projectId=bird_baseline_20261024 with {"query": "<question>"} and read the returned SQL from $.sql. This path called NL2SQL directly; it did not add an adapter.

Rhesis records the endpoint request and returned SQL with each test result. The API response also retained the NL2SQL queryId, threadId, and traceId, which tie the Rhesis row back to the application trace. All 30 requests were question-only.

3. Official BIRD metric: what Pass means​

BIRD Official Execution Accuracy is a deterministic Rhesis Code Metric. It executes both generated SQL and Gold SQL read-only against the fixed PostgreSQL database, then calls the official BIRD functions. Its binary score is 1 when the official execution comparison matches and 0 when it differs. Rhesis uses a 0.5 threshold, so only an exact BIRD pass is marked Pass.

Execution Accuracy ignores row order and duplicate rows; extra or missing columns and different values fail. BIRD Soft F1 measures partial overlap between actual and Gold values. Its official implementation is sensitive to row positions, so use it to investigate near-matches, not as an alternate Pass or Fail verdict. The mean was 0.2802. The official evaluator is pinned to revision abd11b6db92a1c9f809b32f7564c7c71b34d67f0. evaluation_ex.py SHA-256: da1bbcd4530be83692d7c650c814ea9704bb710d0c953eb75d02ccb38233cf89. evaluation_f1.py SHA-256: ba2700ee09b0c34d7e203788544757e6e6d6c99c0425bb92b3daa3927eee29bf.

Why the scorer setting matters: the read-only scoring connection set max_parallel_workers_per_gather=0. This keeps aggregate results stable for the pinned evaluator. All 30 Gold self-comparisons scored 1.0 for both Execution Accuracy and Soft F1. The scoring session used a 30-second SQL timeout. All five table fingerprints matched before and after the run (423,050 rows total).

READ A PARTIAL SCORE AS A CLUE, NOT THE VERDICT

Question 1500 passed official Execution Accuracy while its Soft F1 was 0.0370. Gold returned 976 rows containing 27 unique descriptions; the actual DISTINCT query returned those same 27 descriptions. Official Execution Accuracy ignores duplicate rows, while this Soft F1 implementation is sensitive to row positions. The low partial score does not override the official Pass.
