BIRD Without SQL Pair: 30-Record Analysis Opik

Created: 2026-10-24 · Updated: 2026-10-25

Official BIRD Execution Accuracy is 9/30 (30%): 9 exact matches and 21 mismatches. This report analyzes each result from the same completed experiment, without new model calls or score changes. The baseline setup and Opik guide explains the empty POC, five-table upload, publication, and evaluation workflow. Here, each record shows what matched Gold, what differed, and how to interpret it.

Opik Evaluation and Review adds official Soft F1 and native assertion results for the same 30 outputs. It explains why matching some columns is insufficient, documents judge blind spots, and links to the pending annotation queue.

NO SQL PAIR KNOWLEDGE

SQL Pair Knowledge: NOT USED. Verified in the Snapshot, actual retrieval, and actual generation inputs.

  • Official evidence + Schema RAG: ENABLED. The model receives the question, official hints, and retrieved schema.
  • Gold SQL: SCORING ONLY. It is never included in model requests.
  • Fixed model: mimo-v2.6-flash, temperature 0; a fresh POC project with 5 tables and 30 questions.

1. Baseline setup and inputs​

The dataset contains all 30 public BIRD debit-card questions. Inputs include official evidence and schema retrieval, without SQL Pair Knowledge. The model is mimo-v2.6-flash. Gold means the pinned reference SQL, with reviewed column-name mappings, executed on this POC database. Gold has not been independently certified as business truth. Observable result differences are separated from reference definitions that need review.

2. Official scoring and overall results​

EX compares the set of complete result rows. Row order and duplicate rows are ignored; column order and every column value are retained. There is no automatic column removal, rounding, numeric tolerance, or answer correction. NULL is a database null value, different from zero and from returning no rows. Displayed values retain their recorded precision; display formatting does not create a new score.

Case findings​

The execution pipeline completed; answer quality still needs work. All 30 questions have final results: 9 matching sets and 21 mismatches. Question 1506 retains its intermediate format failure and retry. Zero final errors does not mean no intermediate failures or correct business answers.

Output contracts are a distinct area to investigate. Questions 1472, 1484, and 1486 calculated the target value but added explanation columns. Question 1533 matched the consumption-value set but added customer IDs. Question 1493 introduced rounding. Future work can investigate how to produce the requested fields, granularity, and precision. This run must not gain score through post-scoring column removal, added tolerances, or edited Gold.

Calculation and data-selection differences also matter. Question 1479 omitted CZK filtering; 1490 used a different table and consumption measure; 1498 skipped monthly aggregation. Questions 1505 and 1525 primarily differ in counting records versus distinct customers. These issues cannot all be attributed to missing SQL Pair Knowledge or dismissed because the queries execute.

HOW TO READ THE 30% SCORE

The supported statement is “EX is 30% against this fixed reference set.” It does not establish 30% business accuracy across real use cases. Removing disputed cases to report a better score would change the evaluation. A business-reviewed dataset should be published as a new version, preserving this baseline, and applied to all candidate systems with identical inputs and scoring in a complete rerun.

Original question

Official evidence

ratio of customers who pay in EUR against customers who pay in CZK = count(Currency = 'EUR') / count(Currency = 'CZK').

SELECT
  COUNT(*) FILTER (WHERE c.currency = 'EUR') AS eur_customer_count,
  COUNT(*) FILTER (WHERE c.currency = 'CZK') AS czk_customer_count,

    COUNT(*) FILTER (WHERE c.currency = 'EUR')::NUMERIC
    / NULLIF(COUNT(*) FILTER (WHERE c.currency = 'CZK'), 0),
    4
  ) AS eur_to_czk_ratio
FROM customers c
WHERE c.currency IN ('EUR', 'CZK');

Original question

Official evidence

annual average consumption of customer with the lowest consumption in each segment = total consumption per year / the number of customer with lowest consumption in each segment; Difference in annual average = SME's annual average - LAM's annual average; Difference in annual average = LAM's annual average - KAM's annual average; Year 2013 can be presented as Between 201301 And 201312; The first 4 strings of the Date values in the yearmonth table can represent year.

Gold SQL (read-only scoring version)

SELECT CAST(SUM(CASE WHEN T1.segment = 'SME' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0) - CAST(SUM(CASE WHEN T1.segment = 'LAM' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0), CAST(SUM(CASE WHEN T1.segment = 'LAM' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0) - CAST(SUM(CASE WHEN T1.segment = 'KAM' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0), CAST(SUM(CASE WHEN T1.segment = 'KAM' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0) - CAST(SUM(CASE WHEN T1.segment = 'SME' THEN T2.consumption ELSE 0 END) AS REAL) / NULLIF(COUNT(T1.customer_id), 0) FROM customers AS T1 INNER JOIN yearmonth AS T2 ON T1.customer_id = T2.customer_id WHERE T1.currency = 'CZK' AND T2.consumption = (SELECT MIN(consumption) FROM yearmonth) AND CAST(T2.date AS TEXT) BETWEEN '201301' AND '201312'

Actual generated SQL

WITH czk_2013 AS (
  SELECT ym.customer_id,
         SUM(ym.consumption) AS annual_consumption
  FROM yearmonth ym
  JOIN customers c ON c.customer_id = ym.customer_id
  WHERE c.currency = 'CZK'
    AND ym.date BETWEEN '201301' AND '201312'
  GROUP BY ym.customer_id
),
customer_segment AS (
  SELECT ct.customer_id,
         ct.annual_consumption,
         c.segment
  FROM czk_2013 ct
  JOIN customers c ON c.customer_id = ct.customer_id
  WHERE c.segment IN ('SME', 'LAM', 'KAM')
),
segment_min AS (
  SELECT segment,
         MIN(annual_consumption) AS min_consumption
  FROM customer_segment
  GROUP BY segment
),
lowest_customers AS (
  SELECT cs.segment,
         cs.annual_consumption
  FROM customer_segment cs
  JOIN segment_min sm
    ON sm.segment = cs.segment
   AND sm.min_consumption = cs.annual_consumption
),
segment_avg AS (
  SELECT segment,
         SUM(annual_consumption) / COUNT(*) AS annual_avg_consumption
  FROM lowest_customers
  GROUP BY segment
),
pivoted AS (
  SELECT MAX(CASE WHEN segment = 'SME' THEN annual_avg_consumption END) AS sme_avg,
         MAX(CASE WHEN segment = 'LAM' THEN annual_avg_consumption END) AS lam_avg,
         MAX(CASE WHEN segment = 'KAM' THEN annual_avg_consumption END) AS kam_avg
  FROM segment_avg
)
SELECT sme_avg - lam_avg AS sme_minus_lam,
       lam_avg - kam_avg AS lam_minus_kam,
       kam_avg - sme_avg AS kam_minus_sme
FROM pivoted;
