Opik Test Suites: UI Guide

Created: 2026-10-24 · Updated: 2026-10-25

A Test Suite holds test cases, shared checks, and the pass rule. An Experiment holds one run of the application against those cases. Opik describes these as complementary: suites define pass/fail checks, while experiments store run results and scores in its evaluation concepts.

The local BIRD suite used here

This guide follows bird-question-only-20261024-2134-opik-api, version 3: 30 questions, one Gold SQL assertion per question, three shared assertions, and a default policy of one run with one pass required. Each case’s Data contains the question only. Open this suite in local Opik.

1. Find, create, or edit a suite​

Select Test suites in the left navigation. The list shows each suite’s name, description, item count, most recent experiment, and update time. Click a suite row to open its cases.

Create test suite opens two routes:

Upload a file accepts CSV or JSON. Drop a file into the box or select Browse files. The suite is not created until a valid file is selected and Create test suite is available.

Use SDK opens a form with a suite name, Python and TypeScript tabs, generated starter code, and an optional description. The copy icon copies the displayed code and shows a confirmation toast. The bottom Create test suite button stays disabled until the required name is supplied.

Opik documents visual suite management and SDK setup in Building Test Suites.

Use Search by name for a quick match. The funnel opens a filter builder; its available columns include Name, ID, Description, Tags, Last updated, Created, and Created by.

At the bottom of the list, Rows per page chooses 5, 10, 25, 50, or 100 suites. The arrows move between pages when more suites are present.

Each suite row’s Actions menu contains Edit and Delete. Edit opens the name and optional description fields; Save changes applies them and Cancel closes the drawer.

Selecting a suite checkbox reveals a bulk-delete button and a column chooser. Neither changes data until its action is used.

The gear in the upper-right corner is an application menu, not a suite setting. It opens Support hub and Theme.

2. Read the suite screen​

The suite header shows the version, latest marker, shared assertion count, tags, and the main actions. The rows below are individual test cases.

3. Expand with AI​

Click the wand button. The form detects the current case structure, then asks for a model, a sample count, and optional instructions.

For this suite, Opik detected question in all 30 cases. The default is five samples; the displayed range is 1–200. Generate samples is disabled until a model is selected. Open Generation prompt to inspect or edit what Opik sends to the model:

Opik’s Expand with AI guide recommends reviewing generated items before use.

4. Run the suite and set shared checks​

Click Run to choose one of two paths:

The experiment setup selects the suite and shows installation and example task code. Its task returns a placeholder; the button does not call this project’s NL2SQL API by itself.

See Opik’s Define the task and run guide. The current BIRD API experiment was started with the Python SDK; opening this menu alone does not run it. The code copy icon copies the displayed example and shows a confirmation toast.

The sliders button and the global assertion count open the same Test settings panel. It contains suite-wide assertions and pass criteria.

Shared checkWhat it asks the judge to verify
Population and datesUse the people, records, and time window named in the question.
Calculation and groupingUse the requested measure, formula, denominator, and grouping level.
Requested answerReturn the requested attribute or value; a proxy or empty result does not answer the question.

Default runs per item = 1 and Default pass threshold = 1 mean one run must pass. They set repetition and pass criteria; they do not set parallel workers. Save applies setting edits; Cancel closes without applying them. Opik explains how assertion judges work and execution policies.

5. Add, tag, or inspect a test case​

Click + Test case to open the side panel. Enter the question in Data. For this baseline, that field contains only the question.

Click Add assertion to insert an editable, case-specific assertion field. It starts empty and shows example placeholder text. Manage global assertions opens Test settings.

In the existing BIRD cases, the user’s question stays in Data and that question’s Gold SQL is included in its own assertion. The local API runner reads the question from Data for the request; Gold SQL remains the judge’s comparison criterion. The assertion asks whether the generated SQL is semantically equivalent and does not require identical SQL text.

Opik’s Add test items guide says item assertions are checked in addition to suite-level assertions. A judge pass is a review signal; it is not BIRD execution accuracy.

The tag plus inside the case editor opens an item-level New tag field. The tag plus beside the suite labels applies at suite level.

The case’s top Actions menu contains Share test case, Copy test case ID, and Delete test case. Share copies a case URL; Copy test case ID copies the item identifier. Both show a confirmation toast. Previous and Next move through cases. Deleting a case immediately marks the suite Draft; Save changes commits the deletion, while Discard changes removes the unsaved edit.

Runs for this item and Pass threshold can override the suite defaults. Save changes saves the case; Cancel closes without saving.

To reopen a saved case, use its row Actions menu and choose Edit. Delete stages that case for removal.

6. Search, filter, and manage cases​

Use Search for text in the case table. The funnel opens a filter builder with a column, operator, and value. In this BIRD suite the columns include ID, question, and Tags; operator choices depend on the selected column. Add filter adds a condition and Clear all removes them.

Opik documents filtering by tags and bulk operations.

Select one or more case checkboxes to reveal the bulk toolbar:

ControlWhat it does
Shared tagsOpens Manage shared tags. Add or remove tags, then click Update tags to apply them to every selected case.
ExportDownloads the selected case data as CSV or JSON.
DeleteRemoves selected cases. Opik creates a new dataset version; this guide did not trigger deletion.
DensityOpens Compact, Medium, and Detailed table layouts.
ColumnsShows or hides case fields.

The plus beside the suite labels is separate from the case editor’s tag button and the bulk Manage shared tags action:

7. Review saved versions​

Click Version history to see each version’s change summary, note, tags, item count, time, and author.

Open a version row’s Actions menu. Edit opens version note and tags. Restore makes that older data the latest version without erasing history.

Opik’s version history guide explains immutable versions and restore behavior. No version was edited or restored in this review.

8. Read the evaluation result correctly​

Open Experiments to review a run’s API output, assertion results, and judge explanations. A Test Suite defines the cases and pass/fail rules; the Experiment records what the application returned. Assertion pass rate is not BIRD execution accuracy: the judge checks the written assertions, while BIRD execution accuracy compares query results. See the BIRD baseline review for the 30-question findings and comparison limits.

This walkthrough used the local Opik interface and official Opik documentation. It did not create a suite, upload a file, generate samples, run an experiment, export cases, save edits, or restore a version. The case-delete control was opened during review; its unsaved draft was discarded, and version 3, the original case identifier, and all 30 cases were verified afterward.
