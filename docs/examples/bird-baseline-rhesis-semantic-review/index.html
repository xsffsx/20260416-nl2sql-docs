Rhesis Guide: BIRD Evidence-Based Semantic Review

Created: 2026-10-25 17:58 · Updated: 2026-10-25 21:45

For the three FLEX reference types, their actual 90 outcomes and the full per-question comparison, open FLEX: Three Reference Evaluations.

This run evaluates the business intent expressed by generated SQL. It does not score SQL execution results and is not an official BIRD benchmark score.

QUESTION-ONLY GENERATION

SQL Pair Knowledge was not used. The NL2SQL API received only the question. BIRD evidence was available to the Rhesis judge only; the Test Set contains no Gold SQL.

RESULT FROM THE LOCAL RHESIS UI

20 of 30 passed (66.7%). The judge returned 20 “Meets Business Intent,” 9 “Does Not Meet Business Intent,” and 1 “Needs Human Review.” Rhesis counts only “Meets Business Intent” as passing, so the review case appears in the 10 failures. The run completed all 30 tests in 6 minutes 20 seconds; no human reviews have been submitted.

This is the second run attempt. The first attempt used the previously selected MiMo metric model and all 30 metric calls returned an HTTP 400 error. I created a metric bound to the tested GLM 5.3 BIRD Judge model and ran the test set again. The failed attempt is excluded from the result above.

What goes to NL2SQL and what goes to the judge​

The test input contains the question. Rhesis sends that question to the existing NL2SQL endpoint; the endpoint response is the generated SQL. The metric then sees the question, SQL, and BIRD evidence stored in expected_response. It does not receive Gold SQL, and this metric does not execute SQL or inspect the returned database rows.

Question ──► NL2SQL API ──► Generated SQL
   │                             │
   └──── Question + SQL + BIRD evidence ──► Rhesis CategoricalJudge
                                             ├─ Meets Business Intent  (pass)
                                             ├─ Does Not Meet Business Intent
                                             └─ Needs Human Review

The request record for this run contains only {"query": "<question>"}. The evidence is a judge reference, not generation context. Rhesis calls the field expected_response; here it contains BIRD's expert notes, not a complete answer, reference SQL, or expected result. The official BIRD dataset description describes evidence as external knowledge. The source CSV leaves the evidence empty for questions 1507 and 1528.

For the complete 30-question report with each generated SQL and recorded judge result, open BIRD Without SQL Pair: 30-Record Evidence Rhesis.

1. Check the Test Set fields​

Open the BIRD 30 — Business Evidence Review Test Set. Its Test Prompt is the question and its Expected Response is the original BIRD evidence. Gold SQL is not in the dataset.

Download the 30-question evidence Test Set CSV. Rhesis documents expected_response as an optional expected output and supports CSV Test Set imports; for this run, the field is deliberately used as judge-only evidence. See the official Tests and Test Sets guides.

2. Configure the semantic judge​

The configured metric is Rhesis's native CategoricalJudge. Its rubric asks whether the generated SQL expresses the population, time range, filters, calculation, grouping, and requested output supported by the question and evidence. It says not to compare SQL text, execute SQL, or invent missing schema details. Extra columns alone are not a failure; uncertainty about schema or incomplete evidence should be marked for human review.

Only Meets Business Intent is a passing category. The other two categories remain visible in the judge result, while Rhesis's test-run summary groups them under Fail. This is a task-specific rubric built with a standard Rhesis metric type, not a published universal NL2SQL metric. Rhesis recommends specific criteria, context, and evaluation steps in its custom metric guide and metric configuration guide.

3. Run the test set in Rhesis​

On the Test Set page, choose Execute Test Set and select the existing endpoint NL2SQL API — BIRD question only. The completed run used:

Scoring targetFresh Outputs — call NL2SQL for each question

Rhesis saved the run as crisp-pupa. Its Configuration tab records the endpoint, parallel mode, Fresh Outputs, and Test Set metric. The model appears there as an internal ID; the selected model name is visible in the execution drawer and the metric configuration.

4. Read the outcome​

The run had 30 successful endpoint executions and 30 judge verdicts. The 10 Fail results are not 10 confirmed wrong SQL answers: 9 are “Does Not Meet Business Intent,” and question 1529 is an unresolved schema question. The run's Reviews = 0 means no person has reviewed these cases.

Question 1471: a semantic pass can differ from BIRD exact match​

The SQL returns the requested EUR-to-CZK ratio plus two supporting count columns. The judge marks it Meets Business Intent because the requested ratio is present and correct. BIRD's official Execution Accuracy marks question 1471 0 because the complete result has extra columns. The measures answer different questions; Rhesis's pass does not replace or change the BIRD verdict.

Empty evidence does not automatically mean Fail​

Question 1507 has no BIRD evidence. Its question fully specifies the distinct transaction times for chain 11, so the judge passed the SQL based on the question alone. This is a model verdict, not a human-approved exception.

Missing filters fail; unknown schema needs a person​

For 1509, the SQL counts all transactions after the date but omits the requested Czech Republic gas-station filter. The judge returns Does Not Meet Business Intent. For 1529, the SQL uses date bounds that cannot be checked against the evidence's 201201 date representation without knowing the column type. The judge returns Needs Human Review. Rhesis counts both as Fail because only “Meets Business Intent” passes; neither is a human decision.

Read this score with the right boundary​

The existing no-SQL-pair baseline reports 7/30 official BIRD Execution Accuracy. The new Rhesis run reports 20/30 semantic judge passes. Do not subtract or rank these as competing benchmark scores: one executes SQL and compares full result tables; the other reads SQL and evidence without executing the query. Case 1471 shows why their verdicts can differ.

No person has reviewed these results yet; the one “Needs Human Review” label is the model's classification. This single run is not enough to calibrate the judge as a release gate. Review its disagreements with domain experts and check agreement before relying on it. Model judgments can vary between runs.
