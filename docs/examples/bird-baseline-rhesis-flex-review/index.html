BIRD Without SQL Pair: Three FLEX Reference Evaluations

Updated: 2026-10-25 22:42 (Asia/Shanghai) · Protocol: expected_response required

These are three new Rhesis UI runs, with 30 questions each. There are 76 accepted LLM verdicts, 2 missing-reference errors, 11 other scoring errors and 1 API/SQL failure across all 90 records. Earlier runs are retained in Historical runs.

REFERENCE REQUIRED; GENERATION IS QUESTION-ONLY

The judge must use the testcase's expected_response. An empty JSON field is not a usable answer. Evidence-only questions 1507 and 1528 now stop before SQL scoring and the LLM call, with a missing-reference error and no Pass/Fail score. Gold-only and combined can score those questions because their expected_response contains Gold SQL.

NL2SQL receives only the question. SQL Pair Knowledge is not used. The reference never enters SQL generation.

SDK evaluation code​

End-to-end SDK implementation guide: deployment, WebSocket dispatch, a manually written entry point, and the docs-site data pipeline.

The three metrics in this report run project-written Python code that adapts FLEX and calls GLM-5.3. They are hosted Rhesis Code Metrics, rather than built-in FLEX metrics or metrics created in the Custom Prompt editor. Rhesis UI launches the NL2SQL requests and sends each output to the assigned scoring function.

What runs for each question​

  1. Receive the question, actual SQL and testcase reference. Rhesis passes expected_response to the Python argument expected_output.
  2. Validate the frozen question/reference and required content. Empty Evidence-only references stop here, before SQL execution or an LLM call.
  3. Execute actual and Gold SQL read-only on the frozen PostgreSQL data. Compare the complete results to choose the FLEX branch; this comparison does not decide the final semantic Pass/Fail.
  4. Build the adapted FLEX prompt with the real schema and permitted reference fields. JudgeClient calls GLM-5.3 to judge the actual SQL.
  5. Accept one boolean conclusion: true becomes score 1 and false becomes score 0. Exceptions remain errors; the audit records the actual inputs, request, reply and failure.

Evidence-only uses private Gold to select the branch, but does not send Gold to GLM. Gold-only and combined read their judge-visible Gold SQL from the current expected_response. Each variant evaluates its own fresh NL2SQL output.

def parse_expected_response(variant, payload):

def literal_assignments(source):
    result = {}
    for node in ast.parse(source).body:
        if not isinstance(node, ast.Assign) or not isinstance(node.targets[0], ast.Name):
            continue
        value = node.value
        if isinstance(value, ast.Constant):
            result[node.targets[0].id] = ast.literal_eval(value)
        elif isinstance(value, ast.Call) and isinstance(value.func, ast.Attribute) and value.func.attr == "strip" and isinstance(value.func.value, ast.Constant):
            result[node.targets[0].id] = ast.literal_eval(value.func.value).strip()
    return result


class FlexSource:
    def __init__(self, directory):
        lock = json.loads((directory / "source-lock.json").read_text())
        for name, item in lock["files"].items():

                     isinstance(n, ast.FunctionDef) and n.name in ("get_judge_prompt", "get_system_prompt")]

def digest(value):
    return hashlib.sha256(value.encode()).hexdigest()


def parse_conclusion(content):
    if not isinstance(content, str):
        raise ValueError("Judge content is missing")
    conclusions = list(re.finditer(r"```json\s*\n(\{[^`]*\})\s*\n```", content))
    if conclusions:
        if len(conclusions) != 1 or content[conclusions[0].end():].strip():
            raise ValueError("Expected one final JSON conclusion")
        payload = conclusions[0].group(1)
    else:
        payload = content.strip()
    parsed = json.loads(payload)
    if set(parsed) != {"correct"} or type(parsed["correct"]) is not bool:
        raise ValueError("Judge conclusion must contain exactly one boolean correct field")
    return parsed["correct"]


class JudgeClient:
    def __init__(self, config, api_key):
        self.config = config
        self.client = httpx.Client(base_url=config["base_url"].rstrip("/") + "/",
                                  headers={"Authorization": "Bearer " + api_key}, timeout=config["timeout_seconds"])

    def __call__(self, prompts):
        request = {key: self.config[key] for key in ("model", "temperature", "max_tokens", "thinking", "reasoning_effort")}
        request["messages"] = [{"role": "system", "content": prompts["system"]}, {"role": "user", "content": prompts["user"]}]
        response = self.client.post("chat/completions", json=request)
        response.raise_for_status()
        return response.json()

            strict = self.calculate_ex(result["predicted_rows"], result["gold_rows"]) == 1
            prompts = self.source.prompts(variant, self.manifest["schema"], input, output,
                        expected_output, result["predicted_rows"], result["gold_rows"], strict)
            record["prompts"] = prompts
            response = self.judge(prompts)
            record["judge_response"] = response
            choice = response["choices"][0]
            if choice["finish_reason"] != "stop":
                raise ValueError("Judge response did not finish normally: " + str(choice["finish_reason"]))
            content = choice["message"]["content"]
            verdict = parse_conclusion(content)
            record.update(status="scored", score=int(verdict), correct=verdict, judge_reason=content)
            return {"score": int(verdict), "details": {"reason": content + "\nAudit: " + record["id"]}}
        except Exception as exc:
            record["error"] = {"type": type(exc).__name__, "message": str(exc)}
            raise
        finally:
            record["elapsed_ms"] = (time.perf_counter() - started) * 1000
            write_json(self.audit_dir / (record["id"] + ".json"), record)

FLEX: paper and design intent​

FLEX, Kim et al., NAACL 2025, uses an LLM to review SQL semantics because exact execution matching can accept a coincidentally correct answer or reject a useful answer whose result shape differs. The full method supplies question, schema, predicted/reference SQL and evidence; it adds both execution results when the results differ. Its correctness criteria cover population filters, joins, calculation, NULLs and output differences.

The original implementations are full FLEX, NoHint and NoGroundTruth. We retain their correctness criteria and result formatting, with documented PostgreSQL and reference-input adaptations. Evidence-only still uses private Gold only to select the execution branch; the judge never receives Gold SQL, Gold results or an explicit match hint in that variant.

The paper reports 87.04 Cohen's kappa with experts for full FLEX. That is agreement with human labels, not an 87.04% SQL correctness rate, and it does not validate the GLM-based reference-required runs on this page. Download the published paper · Pinned source and checksums.
