Spider 1.0 CSV and NL2SQL example

Created: 2026-09-25 05:51:19 +08:00 · Updated: 2026-09-25 18:45:54 +08:00

This page packages one official Spider 1.0 development example as three small CSV files. Upload them to a project running POC_CSV_SQL_EXECUTE_RESULT, ask the benchmark question, and compare the generated SQL and result with Spider's gold SQL.

The Spider release stores the database as SQLite and the question/SQL pair in dev.json. The CSVs below are exports of the selected SQLite tables; they are not files distributed in the original release. The exported rows are unchanged.

Where Spider was downloaded​

The source archive used here is spider_data.zip, hosted by the HAL-9001 Spider database mirror. Its dataset card identifies the canonical Yale Spider distribution as its source and records the archive checksum and CC BY-SA 4.0 license.

I downloaded the archive to /tmp/nl2sql-spider/spider_data.zip, checked its SHA-256, and extracted it under /tmp/nl2sql-spider/spider_data/. To repeat that download and check:

mkdir -p /tmp/nl2sql-spider
curl -fL 'https://huggingface.co/datasets/HAL-9001/spider-databases/resolve/main/spider_data.zip' \
  -o /tmp/nl2sql-spider/spider_data.zip
shasum -a 256 /tmp/nl2sql-spider/spider_data.zip
unzip -q /tmp/nl2sql-spider/spider_data.zip -d /tmp/nl2sql-spider

The verified SHA-256 is 00636695dabed6b5f4b8328a16b13e069a2f16591d5efcce57660669c85b121b. The temporary archive and extracted source were removed after exporting the sample. The reusable CSVs are in poc-csv-benchmark/spider-concert-singer/; the copies linked from this page are in docs-site/static/datasets/spider-1.0/concert_singer/.

How to find the tables, question, and SQL​

The official Spider README explains the dev.json fields: db_id, question, and query (the gold SQL). It also describes the database files. The archive places the selected database at spider_data/database/concert_singer/concert_singer.sqlite and the question/SQL records in spider_data/dev.json.

After extraction, these commands locate the source tables and the matching benchmark record:

sqlite3 /tmp/nl2sql-spider/spider_data/database/concert_singer/concert_singer.sqlite '.tables'
sqlite3 /tmp/nl2sql-spider/spider_data/database/concert_singer/concert_singer.sqlite '.schema singer_in_concert'
sqlite3 /tmp/nl2sql-spider/spider_data/database/concert_singer/concert_singer.sqlite \
  'SELECT * FROM singer_in_concert LIMIT 5;'
jq '.[37] | {db_id, question, query}' /tmp/nl2sql-spider/spider_data/dev.json

The database tables are in the SQLite file; the question and gold SQL are a separate item in dev.json. The three downloadable CSVs below are exports of singer, singer_in_concert, and concert from that database. The page's download links are the copies used for the local NL2SQL run.

Official Spider example​

Database: concert_singer · Development record: 37

Question

List all singer names in concerts in year 2014.

Gold SQL

SELECT T2.name
FROM singer_in_concert AS T1
JOIN singer AS T2 ON T1.singer_id = T2.singer_id
JOIN concert AS T3 ON T1.concert_id = T3.concert_id
WHERE T3.year = 2014

The source SQLite query returns six rows. Justin Brown appears twice because the gold SQL does not use DISTINCT.

Try it in NL2SQL​

  1. Open the local development guide and start the app with a project configured for POC_CSV_SQL_EXECUTE_RESULT.
  2. Open Schema → CSV data and select singer.csv, singer_in_concert.csv, and concert.csv together.
  3. Click Review CSV. Check the generated table names, normalized column names, inferred PostgreSQL types, and sample values. Change a type or name if needed.
  4. If the project already has tables with these names, delete those tables from CSV tables in this project before importing again; this workflow does not overwrite or update an existing table.
  5. Click Create tables and import. After import, confirm the three tables are marked Queryable and Artifact Snapshot Gate is PASS.
  6. In NL2SQL QA, ask: List all singer names in concerts in year 2014.
  7. Compare the generated SQL and result below with the Spider gold SQL. Check the selected names and duplicate rows; do not compare only whether both queries execute.

CSV upload screen guide​

From Schema → CSV data, choose or drop the three downloaded files together. The table list below the upload area shows CSV tables already owned by the current project.

Click Review CSV before creating anything. The preview shows each file's row count, proposed table name, normalized PostgreSQL column names, inferred types, and sample values. In this screenshot the same-named tables already exist, so the UI correctly reports that they cannot be overwritten. Delete the existing tables first if you want to repeat the import in this project.

The importer normalizes the headers to PostgreSQL-safe names. For example, Singer_ID becomes singer_id, and Song_release_year becomes song_release_year.

Observed local NL2SQL result​

The local POC run generated:

SELECT DISTINCT s.name
FROM singer s
JOIN singer_in_concert sic ON s.singer_id = sic.singer_id
JOIN concert c ON sic.concert_id = c.concert_id
WHERE c.year = 2014
ORDER BY s.name;

It returned five unique names: John Nizinik, Justin Brown, Rose White, Timbaland, and Tribal King. The set of names matches Spider's gold result, but the row multiplicity differs: Spider returns Justin Brown twice while the generated SQL's DISTINCT returns it once. The generated query also sorts the result; Spider's gold SQL does not specify an order.

This is a one-question result comparison, not an official Spider benchmark score. A full benchmark run requires evaluating the benchmark split against its databases using Spider's evaluator; this page demonstrates how one uploaded CSV example can be traced from source data to gold SQL and compared with the local NL2SQL output.

Source and attribution​

Spider 1.0 is a human-labeled cross-domain Text-to-SQL benchmark. The official release documents the question, SQL, database ID, and schema formats in its GitHub repository. The archive mirror labels the dataset CC BY-SA 4.0 and attributes the source to the canonical Yale distribution.

Please cite Tao Yu et al., “Spider: A Large-Scale Human-Labeled Dataset for Complex and Cross-Domain Semantic Parsing and Text-to-SQL Task,” EMNLP 2018. This page's CSVs are derived from the official concert_singer SQLite database, and the gold question/SQL are from its official dev.json development split.
